## 2. New information architecture

Seven hubs, top to bottom in the order of Justin's day, then **More** and **Settings** at the foot of the sidebar.
Each hub is one page with a tab bar (sticky, under the time-zone bar) and a one-line purpose for the open tab.
The sidebar shows only the hubs; the hub you are in unfolds its tabs underneath it.

### Decisions that could have gone either way

- **Hubs as a shared tab bar, not one giant component per hub.** Each tab is still its own route and page, so URLs,
  page state and deep links are untouched and the change is easy to revert (nav.js + Sidebar + HubTabs).
- **Hub named "Marketing", not "Growth"**, because `/growth` already redirects to the hiring plan.
- **Flight Plan lives in Clients** (onboarding is part of the client lifecycle), not in Work.
- **`/automations` kept** alongside Settings › Automations (same component, two entry points). Justin can drop one later.
- **Pins kept.** Any tab can still be pinned to the top of the sidebar; ⌘K still searches every page, client and project.
- **Section label on page headers** now comes from the hub the page lives in, so headers read the same everywhere.

### Code removed (all grep-verified unreferenced)

### Bugs fixed
- **Projects › type tiles filtered by dollar amount, not type.** `ProjectsHero` overwrote each type's `value` (the type
  key) with its contract total, so clicking a tile set the filter to a number and showed nothing; it also caused a
  duplicate-React-key console error. Total moved to `amount`.
- **HyperCare+ manager (`/orbit-seo/manage`)**: client card was a `<button>` containing a delete `<button>` (invalid
  HTML, console error). Card is now a keyboard-accessible `div role="button"`.
- **Double slash in titles** ("Client //Requests", "Leads //Pipeline", "Mission //Settings", "Every //Automation"):
  `PageHeader` now strips a slash the title already carries.
- `/more` overflowed horizontally at 390px; fixed. Sidebar search label no longer wraps.

### Verification

  opens a defined route, every old route maps to a hub, keys are unique, hubs stay ≤ 7 and tabs ≤ 8).
- All 52 admin routes + hub shortcuts loaded in headless Chromium against the sandbox dev server in QA (fake-data)
  mode: no page errors, no error boundaries, correct hub highlighted; no horizontal scroll at 390px or 1440px on the
  checked pages. The signed-in preview could not be opened headlessly (it needs Justin's login).
- No entity schemas, entity data, backend functions, workflows or `base44/` files were touched. WorkEntry unchanged.
